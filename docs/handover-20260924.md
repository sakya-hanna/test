## 2. 升级顺序与构建

1. 备份服务端数据库，以及手机上导出的笔记与原始对话。保留原应用签名，**不要通过卸载旧应用解决签名不匹配**。
2. 如使用自建 CA，执行 `bash server/deploy/gen-certs.sh <实际服务器IP或域名> <输出目录>`。将生成的 `ca.crt` 复制覆盖 `app/src/main/res/raw/chatnotes_ca.pem`，然后构建客户端。证书 SAN 必须包含应用实际填写的地址。若更换 CA，需要重建并安装客户端。
3. 使用 JDK 17、Android SDK Platform 34、Build Tools 34.0.0 构建：`./gradlew :shared:test :server:test :app:testDebugUnitTest :app:assembleDebug :server:shadowJar`；连接设备后执行 `./gradlew :app:connectedDebugAndroidTest`。
4. 先部署**本源码的新服务端**，再安装客户端 0.2.1。新客户端会先调用 `/v1/hello`，只接受协议 v2；旧服务端会被拒绝。暂时不要让仍在运行的旧客户端与新客户端同时修改同一批笔记。
5. 把 `server/build/libs/chatnotes-server.jar`、`server.p12`、`server/deploy/setup-server.sh` 和 `server/deploy/chatnotes-server.service` 放在部署目录；按脚本说明运行。`server.p12` 的口令默认为 `chatnotes`，自定义口令则作为安装脚本的第三个参数传入。启动后使用 `curl --cacert ca.crt https://<实际地址>:8443/health` 检查 TLS。
6. 用**相同签名**覆盖安装 APK：`adb install -r app/build/outputs/apk/debug/app-debug.apk`。升级后先确认旧笔记、登录状态与原文，再在一台测试设备上开启同步并完成下列验收。

接口协议 v2 的变化：`DeleteResponse` 新增 `rejectedIds`，客户端会检查每个 push/delete 回执。服务端数据库表结构没有变化，但新旧客户端混用仍可能触发旧同步逻辑。

## 4. 真机/服务器验收清单

1. 在测试库中新增笔记→同步→移入回收站→立即同步：其他设备收到删除，本机不出现被拉回的笔记。
2. 在两台设备从同一版本开始分别离线编辑同一笔记，再连网：原笔记和“冲突副本”都存在，正文无丢失；重复同步不再增加副本。
3. 一端删除、一端离线编辑：编辑内容以冲突副本保留；回收站恢复后能重新上传并在另一端出现。
4. 在远端放入分类非法、正文超长或 hash 不符的测试数据：拉取失败但本地旧文件保留，光标不前移，也不无限重复同一页。
5. 编辑或删除笔记后重新索引并生成向量：旧向量清除，搜索只返回当前版本，关键词与语义命中同一笔记只显示一项。
6. 用真实服务器地址和证书验证正常连接；错误 CA、错误 SAN、HTTP URL、错误 token 和旧版服务端均应拒绝。启用管理页时，无凭据/错误凭据返回 401，正确凭据可访问。
7. 在无网络、应用结束进程和重新联网的情况下核对 WorkManager 重试、同步进度与持久数据；用已安装版本相同签名覆盖升级。

## 5. 已知限制与后续工程工作

- 同步仍使用客户端时间戳的 last-writer-wins。**在 pull 完成与 push 发出之间**若其他设备刚写入同一条，服务端缺少比较并交换条件，极窄竞态仍可能覆盖另一端的更新。下一阶段应引入服务端版本号/ETag 与条件写入，并在客户端提供可查看、可合并的冲突中心。
- 本轮没有 Android SDK 和可用 Gradle 发行版，构建错误、Android WebView 行为和真实证书握手需要在开发机及真机验收。先用新服务端和两台测试设备验证后再迁移正式数据。
- 导入 ZIP 仍未设置压缩包展开体积、文件数和内容类型限额；从不可信来源导入可能耗尽存储。下一迭代优先做导入事务、配额和恢复测试。
- 同步服务器目前是单 token、单用户模型；配置备份中的模型 API Key 存在于服务器数据库明文列。正式多用户或团队使用前，需要独立账户、访问控制、密钥托管和服务端备份策略。
- 现有 WebView 采集对平台接口变更敏感；DeepSeek 与 ChatGPT 以外平台未适配。新增平台应各自带协议样例、回归测试和人工核对入口。
